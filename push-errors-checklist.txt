======================================================================
  网站部署常见错误清单 —— 每次 push 前逐条检查
======================================================================

1.  TOML 配置：不要出现重复的 [params] 块
    - TOML 同名 table 后出现的会覆盖前面的，不是合并。
    - 所有 params 必须放在同一个 [params] 块内。
    - push 前检查：grep -c '\[params\]' hugo.toml，结果必须是 1。

2.  NUL 空字节（0x00）污染
    - Write 工具写入文件时，有时会在文件末尾附加大量 00 00 00... 空字节。
    - 后果：Hugo 渲染会输出乱码 ；GitHub Actions 解析 YAML 会直接拒绝执行。
    - push 前检查（对所有文本文件）：
      find . -type f \( -name '*.md' -o -name '*.toml' -o -name '*.yml' \
        -o -name '*.html' -o -name '*.yaml' \) \
        -not -path './.git/*' -not -path './themes/*' \
        -exec sh -c 'n=$(tr -dc "\000" < "$1" | wc -c); \
        [ "$n" -gt 0 ] && echo "NUL($n): $1"' _ {} \;
    - 如发现 NUL，用 tr -d '\000' < file > file.clean && mv file.clean file 修复。

3.  NUL 字节导致 git 无法检测文件变更（极易漏提交！）
    - 文件含 NUL 字节时，git diff 可能显示空白，导致配置修改静默丢失。
    - 2026-06-18 实际案例：hugo.toml 中 imageUrl 已改为 avatar.jpg，
      但含 NUL 导致 git 认为文件无变更，头像配置未被提交，线上仍显示旧图。
    - 防范：扫描 NUL 后再 git diff，确认修改确实被检测到：
      git diff --stat  # 如果改了文件却看不到对应文件，立即扫描 NUL

4.  新增的静态文件（图片、PDF 等）必须显式 git add
    - 配置文件指向了新文件，不等于新文件会被自动提交。
    - git add -A 可以一次性添加所有未跟踪文件，但操作后必须 git status 确认。
    - 2026-06-18 实际案例：avatar.jpg 已放入 static/images/，
      hugo.toml 引用已改为 /images/avatar.jpg，但图片未 git add，
      push 后线上 404，头像不显示。

5.  Hugo 版本与主题兼容性
    - PaperMod 主题有最低 Hugo 版本要求（当前 >= 0.146.0）。
    - 锁定版本前先检查：grep min_version themes/PaperMod/theme.toml
    - push 前检查：grep hugo-version .github/workflows/hugo.yml

6.  Git 子模块（PaperMod）状态
    - 跨系统操作时（Linux VM ↔ Windows），PaperMod 可能显示所有文件被修改。
    - push 前检查：cd themes/PaperMod && git status
    - 如果文件被误标为修改却没有实际改动：git checkout -- .

7.  Git 索引损坏后的连锁问题
    - 报错："bad signature 0x00000000" / "index file corrupt"
    - 解决：rm -f .git/index && git reset --soft HEAD && git add -A
    - 注意：reset 后 PaperMod 可能从 submodule 变成 embedded repo，
      需要 git submodule update --init 恢复子模块状态。
    - 提交后检查 git show --stat HEAD 确认没有意外提交 PaperMod 内部文件。

8.  Hugo 模板中缺失的 partial
    - PaperMod 新版本可能引用旧版本不存在的 partial（如 google_analytics.html）。
    - 报错信息："partial xxx not found"
    - 解决：在 layouts/partials/ 下创建空占位文件。

9.  KaTeX 数学公式渲染
    - PaperMod 不内置数学公式支持，需手动配置。
    - KaTeX auto-render 的 $ 有严格的边界检测：$ 前后不能紧挨非英文字符。
      如 "，$\frac{x}{y}$" 中逗号贴 $，KaTeX 拒绝渲染。
    - Goldmark 会把 \( 当成转义吃成 (。
    - 正确方案：用 \\(...\\) 写在 Markdown 里，自定义 JS 渲染函数用 \x5c 表示反斜杠。
    - push 前检查：确认 layouts/partials/extend_head.html 有 KaTeX CSS+JS
    - push 前检查：确认 layouts/partials/extend_footer.html 有自定义渲染函数

10. CDN 的 SRI（完整性哈希）不要随意加
    - integrity + crossorigin 会让浏览器静默拒绝加载哈希不匹配的脚本。
    - 除非你完整验证过哈希值，否则去掉 integrity 和 crossorigin 属性。

11. Hugo --minify 会截断 iframe 属性
    - Hugo 内置 HTML minifier 会把 height="800px" 截断成 height="800。
    - 导致 iframe 高度回退到默认极小值（~150px），显示为一条缝。
    - 解决：CI 中不要加 --minify（PaperMod 资源本身已压缩）。

12. 写入文件优先用 bash heredoc，少用 Write 工具
    - Write 工具有两个已知问题：(1) 文件末尾附加 NUL 空字节；
      (2) 长内容可能在某处被截断（如 iframe 标签被砍掉后半截）。
    - 可靠方案：用 bash 的 heredoc 写入文件内容：
      cat > path/to/file.md << 'EOF'
      内容...
      EOF
    - heredoc 的 'EOF' 加引号可防止变量展开和转义干扰。

13. Frontmatter 分隔符一致性
    - +++ (TOML) 和 --- (YAML) 混用虽然 Hugo 都接受，但不规整。
    - 统一用 --- (YAML)。

14. 页面内容中不要写与 frontmatter title 重复的 ## 标题
    - Hugo 会自动渲染 frontmatter 中的 title 为页面 h1 标题。
    - 如果正文第一个就是 ## 同名标题，页面上会出现两个一样的标题。

15. 列表页摘要（summary）要显式写
    - PaperMod 在列表页自动从正文截取摘要，会洗掉链接、分割线等格式。
    - 每个 content page 的 frontmatter 里加 summary 字段可避免此问题。
    - 示例：summary: "这是一段清晰可读的摘要"

16. 内容文件不要复制到错误的目录
    - 如 math-analysis/advanced-algebra.md 与 linear-algebra/ 下内容完全重复。
    - 新建文件前先确认其内容该属于哪个目录。

17. GitHub Actions 部署失败静默
    - 如果 push 后网站没更新，去 Actions 页面看构建日志：
      https://github.com/stockfish-ooo/stockfish-ooo.github.io/actions
    - 别只看 "push 成功"，要看 Action 是否绿勾。

======================================================================
  push 前快速检查命令（每次执行，不要跳过）
======================================================================

# 1. TOML 唯一 [params]
grep -c '\[params\]' hugo.toml

# 2. NUL 空字节扫描
find . -type f \( -name '*.md' -o -name '*.toml' -o -name '*.yml' -o -name '*.html' \) \
  -not -path './.git/*' -not -path './themes/*' -not -path './public/*' | \
  while read f; do n=$(tr -dc '\000' < "$f" | wc -c); \
  [ "$n" -gt 0 ] && echo "NUL($n): $f"; done

# 3. 确认 git 能检测到所有文件修改
git diff --stat           # 修改的文件
git diff --cached --stat  # 已暂存的文件
git ls-files --others --exclude-standard  # 未跟踪的新文件

# 4. 本地构建测试（不用 --minify）
hugo 2>&1 | tail -8

# 5. 检查 iframe 完整性
grep -r 'height=' public/ | grep -v '800px' | grep -v '800"' || echo "iframe OK"

# 6. PaperMod 子模块状态
cd themes/PaperMod && git status && cd ../..

# 7. 最终确认
git status
git log --oneline -3
